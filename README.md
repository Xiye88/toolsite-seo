# Toolsite SEO · 工具站实战手册

从工具站实践中提炼、持续更新的 Agent Skill。帮助独立开发者完成需求验证、产品与设计、开发、技术 SEO、上线、收费及增长复盘。

**当前版本：0.1.1 · 2026-10-25。** 只公开通用方法、匿名经验和模板，不披露自有产品名称、域名、链接或经营数据。已经上线不代表获得排名或收入。

## 如何使用

将本仓库作为一个完整的 Skill 安装，保留 `references/` 与 `templates/`。以下以 Codex 为例；其他支持 `SKILL.md` 的 Agent 可使用自己的技能目录。

```sh
git clone https://github.com/Xiye88/toolsite-seo.git "$HOME/.codex/skills/toolsite-seo"
```

目标目录若已存在，先确认现有来源，不要覆盖。安装后在新的聊天中调用：

```text
$toolsite-seo 我想做一个面向某个国家的工具站，请先帮我验证关键词和搜索意图。
$toolsite-seo 检查这个现有工具站的上线准备，只补缺失项。
$toolsite-seo 把这次上线踩坑整理为一条可复用经验，并更新对应参考文档。
```

它是工作流程与证据模板，不是网站源码生成器。没有付费 SEO 账户、MCP 或其他 Skill 也能开始；缺少数据时说明结论限制。操作范围及发布、费用等授权以当前用户指令为准。

## 持续积累的方法

1. 在项目中用经验模板记录现象、证据、原因、修复、验证及适用范围。原始日志与敏感数据留在项目私有空间。
2. 项目 PM 或负责的 Agent 检查：这是一次偶然现象，还是可复用规则？尚无充分证据的保留为待验证假设。
3. 将通用规则合入对应 `references/`；项目背景、来源映射和原始证据保留在私有项目文档。只有需要改变入口或执行顺序时才改 `SKILL.md`。
4. 记录核验日期、适用条件及失效条件，更新 [CHANGELOG](CHANGELOG.md) 并提交。以后有新经验时先匿名化，再加入对应章节，不把项目交付流水搬进公开仓库。

一次发布至少检查：Skill 元信息可读、相对链接有效、第三方许可清楚、事实与假设分开。默认不公开自有项目名称/域名/链接、精确查询词与市场组合、经营数据、价格、版本时间线、内部路径或身份信息；文件名、提交消息、仓库简介及 Git 历史也纳入检查。产品本身能公开访问，不等于获准在方法仓库关联披露。需要实名案例时另有明确授权。

修正文案提升补丁版本；加入兼容的新经验提升次版本；改变执行约定时说明迁移方法。

## 与其他 Skill、MCP 的关系

已有 `rankup` 可继续承担更广的建站与增长调度；本仓库提供工具站匿名经验、验收方式和可复用模板。`gefei-seo-toolbox`、`ui-ux-pro-max`、`claude-design`、`web-design-guidelines` 等按任务选用，不能把“已安装”当作“已执行并验证”。不自动安装所有工具，也不要求迁移技术栈。

开源工具的入口、许可证与外部服务的区别见[设计与工具](references/design-and-tools.md)。本包不包含第三方 Skill 源码、付费教程、字体/图片素材库或 API 凭证。
