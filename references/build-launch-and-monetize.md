# 实现、发布、数据与可选收费

按当前工作读对应章节；已有验收有效时沿用，不把本参考变成每次全量重测清单。以实际技术栈为准，以下约束可用于不同框架、托管与数据库。

## 1. 接管、接口与证据

先检查仓库状态、实际依赖、生成代码、部署环境与最新生产来源；历史主目录可能落后于独立 worktree。记录未提交文件，合并时保留他人修改。没有远程主分支时，部署回执可能是当时唯一的生产版本线索，不能默认为本地 HEAD。

并行实现前先约定共享数据与文件所有权：输入校验、生成快照、当前产物、场景选项、语言、导出接口。核心引擎/构建/依赖指定集成者；Logo、模板、文章、翻译、QA 可按接口拆分。代理额度不足或中断就接管未完成项，不能把已派发写成已完成。

外部审计线索分为：已复现、当前已修、未复现、未测/外部条件不足、产品既定规则。复现脚本可以保留红色历史结果；不要通过改断言、删失败证据制造全绿。

证据应关联版本、环境、输入类别、实际行为、输出文件及限制。不同测试集合有重叠时不机械相加；测试总数不是用户成功次数。

## 2. 输入到最终文件的一致性

### 一个被验证的当前产物

对生成、转换、排版类工具，预览、下载、打印、复制应消费同一份不可变生成结果。输入一旦变更，旧产物失效；正在运行的旧异步任务完成后也不能覆盖新状态。

可用的最小做法：

- 提交时统一读取/校验快照，生成任务带版本；渲染结束仅在版本仍当前时提交。
- 输入/场景/Logo/语言等影响产物的修改立即清除或禁用旧导出；失败不能重新暴露上一份有效文件。
- 导出前再次核对当前输入与生成快照，防止无 input/change 事件的程序化修改绕过保护。
- 确认产品是否要求“编辑后旧码立即失效”。早期“快照内部一致”测试不等于这一新要求已通过。

金额等精确十进制输入使用合适的十进制表示，不以浮点转换破坏原值。字段/图片/批量上限是工程资源限制时明确说明，不伪装成银行或官方协议要求。URI 编码使用标准库，再独立解析核对特殊字符和目标字段。

### 验实际结果

检查真实下载的非空文件、格式头/尺寸/页数及可读内容。QR 用独立解码器核对实际 PNG/PDF 中的数据；其他工具相应使用独立解析器、重开文档或数据往返校验。DOM 提示“成功”只能证明提示出现。

浏览器下载事件超时可能来自自动化桥、原生窗口或文件获取路径；先查真实文件与下载状态，再判断产品缺陷。保留未取得文件的失败记录，不把 PDF 导出、浏览器打印对话框和实体纸张输出混为一项。

QR 的预览 CSS 尺寸应与导出像素分开；Logo 中心覆盖需要纠错与实际解码保护，顶部 Logo 不应遮挡码区。静区、对比度、打印大小和字体均影响结果。解码通过不证明目标支付 App 接受，更不证明到账。

图片/CSV/解码器尽量本地处理；限制文件大小、像素和数量，拒绝不支持的主动内容格式。解码只呈现分类和内容，不自动打开未知链接；本地解析不应悄悄把原文存入浏览器持久缓存。

## 3. SEO、多语言与页面价值

为独立任务创建页面：页面的默认场景、控件、说明、例子和输出要与搜索意图一致。共享表单的无关字段应在该场景真正隐藏/禁用；不要根据源码中存在字段就认定用户看得到。

- 初始 HTML 提供主标题、独立说明、真实内容和可发现链接；不要只在客户端挂载空壳。
- 唯一 title/description、一个主 H1、自引用 canonical；语言页用正确的语言/地区代码互指，x-default 依实际路由规划设置。
- 核对内链、语言切换、帮助/政策入口、404 及目录重定向。功能按钮和文章链接文案区分 Open tool/Read guide，辅助技术名称也要准确。
- Sitemap 按预期索引 URL 集合比对，检查唯一性、缺失和多余项；登录/结果/后台等不应因数量目标被纳入。
- noindex 是项目索引策略的一部分。政策页是否索引按实际需求决定，不把某个项目的选择当作通用规定。
- 结构化数据与真实可见内容一致，不为了丰富结果标不存在的能力、评分或 FAQ。

Sitemap 的生成与公开不依赖 GA4 配置或其他搜索引擎审核。网站所有权验证、Sitemap 提交成功、URL 被发现、被抓取、被索引分别留证；其中任一完成都不能自动填满后续状态。保留已提交资源，正常内容更新通常不需要反复重建关联或提交同一 Sitemap。

第二语言覆盖初始 HTML、页面元数据、导航、表单、验证、状态、价格/续费、导出文本和错误。自托管合适字体并检查 PDF 的实际字形；切换语言后的输入/旧产物状态应符合隐私和一致性约定。自动翻译通过测试不代表母语审校完成。

涉及银行或金融规范的文章优先核原始官方来源；PDF 抓取失败、搜索摘要或旧资料只能支持有限陈述。去掉无法核实的新版本/年份断言，比补写一个听起来可信的规定更好。品牌、App 或国家名不构成已实测兼容声明。

## 4. Preview、生产与回滚

Preview 前实际确认生产分支；分支名称看起来像预览不构成隔离证明。使用测试资源，HTTP 响应/HTML 检查 noindex，统计按正式域名门控，避免 QA 污染生产。第三方收银台返回地址也属于环境隔离范围。

发布交接至少包含：固定部署 URL、分支别名、Deployment、Commit、构建标识/指纹及验收记录。别名可能移动，独立测试使用固定版本。

发布前重新核对当前生产；将验收改动安全合并到最新代码，保留其他线程已上线的页面、功能和配置。需要改代码时重新构建并验证相关差异，不能仍声称与旧 Preview 产物完全相同。

上线只做与变更相关的冒烟：代表性真实操作/文件、路由/元数据、私有接口权限、语言/移动端、敏感数据边界。记录哪些是复用旧证据，哪些是新的生产验证。出现确认的安全/阻断问题时按当前授权停止或回滚。

回滚回执记录上一生产版本与恢复方法。应用代码回滚不恢复数据库、不撤销外部订单，也不自动取消订阅。收费事故可先停止新购买，继续接收已有客户的取消/退款回调；不能一刀切删除账本或密钥。

## 5. 统计、隐私与真实收数

先查已有属性/流/关联，不因页面没显示数据就新建一套。迁移后实际核 Measurement ID，警惕截图抄写相近字符错误。复用已验证的事件名，业务枚举新增时补白名单；旧名与新名并存的历史报表不自动意味着当前双发。

在用户同意约定下测试四种状态：未选择、同意、拒绝、撤回。取消自动弹窗不会使“未选择”变成允许；已有记录应保留，并有可找到的设置入口。已同意用户仍可正常发送事件。低打扰设计会减少未主动同意访客的统计，不能宣称覆盖所有访客。

事件只用必要固定枚举/布尔量。阻止输入值、收款标识、姓名、金额、支付链接、QR 原文、文件名、CSV、邮箱、OTP、账户/订单标识进入统计；清理 page_location/referrer 的查询与片段，检查增强测量是否会额外采集表单/下载等信息。

验证分层：

1. 页面与网络：无同意不加载；一次动作只发预期事件；参数符合白名单。
2. 传输：请求发送或 204；这仍不是后台入库证明。
3. 后台：正确项目的 Realtime/报表实际出现对应事件，保存时间和测试干扰说明。
4. 业务语义：生成、下载发起、打印对话框、复制、真实付款是不同事件。没有服务端付款证据不得发送成功购买。

工具操作事件不一定覆盖完整付费漏斗；不要为了补齐图表而从返回 URL 推导支付成功。账户/Checkout 是否加载分析按产品隐私方案决定。

## 6. 有真实需要时接收费

### 可用性先于开关

确认商户实际 Approved/Live Enabled、产品周期/币种/价格、目标国家支付方式和所需真实主体资料。后台审核中不阻塞无依赖代码开发，但也不能绕过审核开收费。

工具输出中的收款请求与网站自身收取的软件订阅费可以是两条不同业务；支持国际卡不代表支持目标市场的本地支付方式。公开定价、税费、续费、取消、退款说明必须与真正的商品/政策一致。真实身份、银行/公司信息由所有者提供，不能用营销文案填空。

使用托管 Checkout，服务端决定商品、价格、币种、用户和环境；客户端仅传允许的套餐枚举。测试密钥、商品、Webhook、数据库与生产隔离。密钥通过平台加密 Secret 私下保存，验证存在/可用时避免回显；发现泄漏按授权立即作废替换，删除聊天文字不能作废密钥。

### 付款到权益

- OTP 发送成功、验证码有效和安全会话分别验证；发送失败不能仍返回“已发送”。保护频率、过期、重试、HttpOnly cookie，避免把 session token 返回前端 JSON。
- 签名校验使用支付方要求的原始请求体；核对环境、商店、订单/Checkout、用户、币种、金额与套餐，绑定可信服务端记录。
- 回调幂等键依据当前官方语义与真实报文决定。供应商的顶层 id 可能在同一订单的不同事件中复用；不能直接将所有 id 当独立投递 UUID，也不能把 `eventType:id` 当适用于所有供应商的固定公式。
- 事务性地认领事件并更新订阅/权益；重复同内容安全重试，冲突/乱序/终态按契约处理。返回页 success 参数和前端 Pro 标志不授予权限。
- 服务端保护付费 API、运行时代码和最终导出，重新检查当前订阅/权益；隐藏按钮只改善体验。已经交付到浏览器的文件无法被当作可撤回 DRM。
- 按产品政策检查取消未来续费、付费周期末、欠费、终止、退款成功/失败、到期及重放。取消续费通常不等于立即撤权；失败退款不应无故撤权；已确认退款/到期不能残留不应存在的权限。

### 四种状态分开写

| 状态 | 所需证据 |
| --- | --- |
| 已落地 | 实际代码、配置及可运行路径 |
| 测试通过 | 明确是本地签名夹具还是支付方真实 Sandbox 回调/数据库/权益 |
| 生产开通 | Live 商户/商品/密钥/Webhook就绪，正式登录与购买入口实际开放 |
| 真实业务成功 | 用户授权真实付款，可信 Production 回调、订阅、权益匹配；到账/提现另有证据 |

沙盒成功不是结算成功；Live 收银台打开也不是成交。真实首笔消费由当前授权决定，不替用户填写真实银行卡或选择 VPN 推断的国家。

## 7. 反馈后台与管理权限

可用下载后的轻量问卷收集后续需求，触发点要在实际下载发起后；可跳过、可手动打开、一次邀请、双语，不能阻断文件。匿名反馈不改变 GA 同意；建议文本提示并过滤明显敏感内容，限制长度、频率、保留期和查询量。候选功能只是调研，不写成路线图承诺。

只读管理页/汇总 API 使用已验证会话与服务端显式角色，免费/Pro身份不等于管理员。匿名给清晰登录入口，成功后安全回跳；已登录无权限显示可切换账号的提示。回跳地址使用允许列表，避免开放重定向。权限查询和路由配置都要核对，不能用前端隐藏或全员提权修复访问问题。

## 8. 上线后的增长判读

先固定对比窗口、国家、语言、页面/查询、设备、数据源及变更日期。保留同意率、QA/debug、报表延迟、采样和缺失数据的限制。选择一个问题推进，而不是“没增长就全部重做”。

| 观察 | 优先检查 | 下一步与验证 |
| --- | --- | --- |
| 未抓取/未发现 | 真实状态码、robots、Sitemap、可爬内链、初始 HTML、发布时间 | 修发现/访问障碍，等待正常抓取并复查代表 URL；不循环提交 |
| 已抓取未收录 | GSC 排除原因、Google canonical、内容差异、功能价值、软404/重复 | 按实际原因改善单页；没有原因数据先记不足，不批量改 URL |
| 有展示无点击 | 查询意图、位置/版面、标题说明与真实内容、国家设备 | 对有足够样本的页面做有依据的文案/匹配调整；展示数不是访问 |
| 有访问无核心动作 | 先核统计同意/事件，再看入口、表单、错误、速度和移动使用 | 复现用户任务，修操作障碍；不要以缺事件认定所有用户放弃 |
| 有使用无收入 | 付费价值、真实权益、价格/币种/支付资格、漏斗未观测段 | 查可信业务记录/反馈；不能把所有工具访客都当付费目标 |

报告按“事实→解释/假设→本次改动→观察条件”写。少量展示的平均第一不能宣传全面排名第一；开发者和 Tag Assistant 测试流量不能包装成客户增长。没有新证据时保持站点稳定，不无故改 Sitemap、扩同义词页或许诺 N 天排名。
